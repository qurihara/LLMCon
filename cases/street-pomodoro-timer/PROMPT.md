# Street Pomodoro Timer を自分の環境で使えるようにするためのプロンプト

このファイルは、大規模言語モデル（以下 LLM）のコーディングエージェントに読ませるためのものです。
Claude Code などのエージェントに、次のように頼んでください。

> このフォルダの PROMPT.md を読んで、私の環境で Street Pomodoro Timer を使えるようにして。

この先の節に、そのエージェントに向けた指示を書きます。

---

## 1. 作るもの

Street Pomodoro Timer は、ポモドーロテクニック（25分の作業と5分の休憩を繰り返す時間の使い方）の休憩を、
対戦格闘ゲーム「ストリートファイター6」（以下 SF6、© CAPCOM）で過ごすためのタイマーです。
LLMCon（大規模言語モデルから MCP で操作できる仮想ゲームコントローラ）を通して SF6 を操作します。

一周期の流れは次のとおりです。

1. 作業の段階（既定25分）。画面の下の中央に、残り時間を重ねて表示する。作業の間は SF6 の音量を下げる。
2. 準備の段階（作業の終わりの約16秒前）。SF6 のトレーニングモードのメニューを LLMCon から操作し、
   カジュアルマッチ（オンラインの対戦相手の検索）を始める直前まで進める。
3. 作業の終わりの時刻ちょうどに、メニューを閉じる1手を送り、カジュアルマッチの検索を始める。
   **この準備と検索の開始は、利用者が明示的に有効にしたときだけ行う（4節を参照）。**
4. 休憩の段階（既定5分）。利用者が自分のコントローラで対戦する。SF6 の音量を元に戻す。
5. 休憩の終わりから、LLMCon が利用者の入力を段階的に操作しにくくしていく（入力の遅延、特定のボタンの無効、
   ボタンの入れ替え）。利用者がゲームをやめて作業に戻るのを助けるためである。入力が15秒途切れたら解除する。

実行中の経路に LLM は入っていません。タイマー、メニューの手順、制限の段階は、すべて決まったプログラムで動きます。
LLM の役割は、このプロンプトと参考のコードを読み、利用者の環境に合わせて組み立てることです。

## 2. 参考のコード

`reference/` に、作者の研究室の環境（ROG Ally、Windows、アーケードスティック）で動いているコードの写しがあります。
**まず `reference/` のすべてのファイルを読んでください。** 読んだうえで、利用者の環境に合わせて直して使います。
一から作り直したい場合でも、3節の罠の一覧は必ず読んでください。

| ファイル | 役割 |
|---|---|
| `pomodoro.py` | タイマーと段取りの本体。HTTP で状態を返し、一時停止、再開、リセット、設定の変更、停止を受け付ける（既定は 127.0.0.1:8810） |
| `overlay.py` | 画面の下の中央に重ねる表示と、読み上げ（`voice/` の WAV、無ければ Windows の音声合成） |
| `restrict.py` | 休憩の終わりからの操作しにくさ。`plans/street-fighter-6.json` の制限から選んだものを、段階を上げながら MCPCon に送る |
| `ensure_training.py` | SF6 が動いていなければ Steam で起動し、画面を見分けてトレーニングモードの対戦画面まで進める |
| `setup_pad.py` | 利用者のパッドを MCPCon の物理パッドとして選び、軸を割り当てる |
| `volume.py` | 作業の間だけ SF6 の音量を下げる（pycaw） |
| `start_pomodoro.ps1` | 上のものを1回で起動する Windows の PowerShell のスクリプト。`-Stop` で止める |
| `route.sf6_training.json` | トレーニングモードの対戦画面からカジュアルマッチの検索を始めるまでのボタンの手順 |
| `control.html` | 別の機械やスマートフォンから操作するための画面 |
| `mcp_client.py` | MCPCon を呼ぶための小さな MCP のクライアント |
| `test/` | MCPCon のシミュレーションを相手にした試験。実機が無くても動く |

## 3. 罠の一覧（作者の環境で実際に起きたこと）

次の罠は、どれも作者の環境で実際に起きました。利用者の環境でも起きる可能性が高いものです。

- **SF6 は、ウィンドウが前面にないとパッドの入力を受け付けない。** 重ね表示のウィンドウやコンソールのウィンドウが前面を取ると、
  利用者がボタンを押しても何も起きない。LLMCon は入力を渡し続けているので、LLMCon の側の記録を見ても気づけない。
  重ね表示のウィンドウには前面を取らない設定（WS_EX_NOACTIVATE など）を付け、起動のあとに SF6 を前面に戻す。
  「ボタンが効かない」と言われたら、最初に前面のウィンドウを確かめる。
- **SF6 は、起動したときにつながっていたコントローラを使い続ける。** LLMCon の仮想のパッドで操作するには、
  MCPCon（LLMCon の本体）を先に起動し、そのあとで SF6 を起動する。
- **SF6 が仮想のパッドだけを見るので、利用者のコントローラも MCPCon を通す。** MCPCon の物理パッドとして利用者のコントローラを選ぶ。
  こうすると、休憩の終わりの制限も利用者の入力に掛けられる。
- **コントローラの軸の割り当ては機種ごとに違う。** MCPCon の get_pad_raw で各軸の値を読み、set_pad_axes で割り当てる。
  作者のアーケードスティックでは、既定のままだと L2 が右スティックの縦として読まれ、右スティックが上に入り続けた。
- **コントローラを抜き差しすると、MCPCon は古い取っ手を持ったままになり、値を受け取らなくなることがある。** 選び直すと直る。
  ただし、レバーとボタンを放している間は報告を送らない機種もあるので、時刻印が止まっているだけでは故障とは言えない。
- **カジュアルマッチの検索は、ON にした時点ではなく、B でメニューを閉じた時点で始まる。** メニューを開いている間は「一時停止中」になる。
  そのため、ON にするまでを事前の準備として済ませ、作業の終わりの時刻ちょうどに B を送る。
- **準備の手を送ったあとは、誰かが B を1回押すだけで検索が始まる状態になる。** オンラインの機能を有効にしていないときは、準備の手も送らない。
- **トレーニングモードのメニューのカーソルは前回の位置を覚えている。** BATTLE SETTING の画面のカーソルは、毎回ランクマッチから始まる。
- **準備の直前に画面を確かめる。** 利用者がトレーニングモードに戻し忘れていると、メニューの手が別の画面へ送られる。
  トレーニングモードの対戦画面でなければ、その回の準備をやめる。
- **タイトル画面（PRESS ANY BUTTON）は、A だけでは進まないことがある。** 起動の直後は入力を受け付けないことがあるので、数秒待ち、Start と A を交互に押す。
- **画面の見分けは、言語の設定、画面の解像度、操作の方式（クラシックかモダンか）で変わりうる。** `ensure_training.py` の判定は作者の環境（日本語、1920×1080 と 1280×720）で確かめたもので、
  色の割合の閾値は利用者の画面で確かめ直す。
- **入力の各段は3フレーム以上にする。** 2フレームでは段が消えることがあった。
- **読み上げは1本の待ち行列で鳴らす。** 読み上げのたびに別の処理を起動すると、声が重なる。
- **休憩の終わりの制限でも、メニュー（Start、Back）、方向、決定（A）、キャンセル（B）は常に動くようにする。**
  対戦のあとにカジュアルマッチの待ち受けを止める操作を妨げないためである。`restrict.py` はこれらに掛かる制限を取り除く。
- **強制終了すると、SF6 の音量が下がったまま残る。** 止めるときは、先にタイマーに停止を頼む（POST /stop）。

## 4. オンラインの機能は既定で切る（必ず守る）

**オンラインの対戦で自動の入力を使うことが、SF6 の利用規約でどう扱われるかを、作者は確かめていません。**
そのため、作業の終わりにカジュアルマッチの検索を自動で始める機能（`pomodoro.py --allow-online`、`start_pomodoro.ps1 -Online`）は、既定で切ってあります。

- オンラインの機能を切っている間は、メニューの手を1つも送りません。作業と休憩のタイマー、重ね表示、読み上げ、音量の切り替え、
  休憩の終わりの制限（オフラインのトレーニングモードでも働く）は使えます。
- 利用者がオンラインの機能を有効にしたいと言ったら、上の事情を伝え、SF6 の利用規約を利用者自身が確かめたうえで判断するよう求めてください。
  エージェントが自分の判断で有効にしてはいけません。
- 対人の場で相手に知らせずに入力を改変する使い方は想定していません（LLMCon の README の「使ってよい場面」を参照）。
  休憩の終わりの制限は、利用者自身の入力にだけ掛けます。

## 5. 進め方

1. `reference/` のすべてのファイルと、LLMCon の README を読む。
2. 利用者に次のことを確かめる。1問ずつ尋ねる。
   - LLMCon（MCPCon）がどこにあるか。動いているか。
   - 使うコントローラの機種と、SF6 の操作の方式（クラシックかモダンか）。
   - 画面の解像度と、SF6 の言語の設定。
   - 作業と休憩の長さ（既定25分と5分）。
   - 重ね表示と読み上げを使うか。
3. 実機に触れずにできることから始める。`test/` の試験を回し、MCPCon のシミュレーションで動くことを確かめる。
4. `setup_pad.py` で利用者のコントローラを選び、get_pad_raw で軸を確かめて割り当てる。
5. `ensure_training.py --dry-run --no-launch` で、利用者の画面を正しく見分けるかを確かめる。合わなければ閾値を直す。
6. オフラインで、短い周期（たとえば作業1分、休憩0.5分）で通して動かし、重ね表示が出ても SF6 が前面のままか、
   利用者の入力が SF6 に届くか、休憩の終わりの制限が掛かるかを、利用者に確かめてもらう。
7. 本番の長さで使う。
