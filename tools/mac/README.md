# mac から LLMCon を動かして測る道具

macOS の画面を持たないホスト（`CntlLevelConnection.Host`）と、画面を持たない Chrome を
組み合わせて、ブラウザで動くゲームを外から操作し、自動で測るための道具である。
標準ライブラリと `websocket-client` だけで動く。

**この道具立ての使い方と、踏むと必ず時間を溶かす罠は、手引き `skills/game-extension/SKILL.md` に
まとめてある。** 測定を始める前にそちらを読むこと。

## 部品

| ファイル | 何をするか |
|---|---|
| `llmcon.py` | LLMCon を遠隔から操作する。`Mcp` が MCP のツールを呼び、`VCon` がウェブ版コントローラと同じ経路で人間入力を送る |
| `browser_gamepad.py` | 画面を持たない Chrome を操る。Gamepad API を見せる経路と、キーボードの事象へ変換する経路を注入する |

**改変ルールを効かせたい入力は `VCon` から送る。** MCP のツール（`hold` や `set_stick`）で
送った入力は大規模言語モデルによる注入として扱われ、改変が効かない。

## 測定

| ファイル | 何を測るか |
|---|---|
| `measure_sensitivity.py` | 感度を落としたときの「狙った位置に自機を置けた割合」。対照つき |
| `measure_delay_v2.py`, `tetris_agent.js` | 反応遅延を掛けたときの「意図した列に置けた割合」 |
| `connect_two_games.py` | 2つのゲームを接続し、並びの成立で相手のボタンが止まることを確かめる |
| `play_three_cases.py` | 一対多の分配、自分自身への接続、片手のコントローラ |
| `referee.py` | 画面を見た大規模言語モデルが改変ルールを調整するループ。段階を追って呼ぶ |
| `measure_cross_latency.py` | 別々の計算機をまたいだ接続の遅延 |

## 指標の選び方

**ゲームのスコアを指標にしてはならない。** スコアはそのゲームが面白くなるように設計された
合成値であって、操作の巧拙だけを表さない。実際、あるテトリスの再実装はソフトドロップ1回で
1点入るため、反応遅延を掛けたほうがスコアが高くなった。

代わりに「意図したとおりに操作できたか」を直接測る。許容幅は自分で決めず、
そのゲーム自身の当たり判定から取ること。
