# ゲーム集（CntlLevelConnection）

## 目的

これは LLMCon / KuriCon の仮想コントローラの効果を試すためのゲーム集です。
5 つの小さなブラウザゲームが入っています。

KuriCon や LLMCon で仮想コントローラを動かし、そこに反転・遅延・連打・アナログ変換・
マイクといった改変を掛けると、ゲームの操作感が変わります。各ゲームの右上には入力表示（HUD）が
あり、実際にどのボタンや軸がどう入ってきているかが見えるので、改変の前後で入力がどう変化するかを
体験できます。

`index.html` をブラウザで開くとランチャーが表示され、各ゲームへ移動できます。すべて 1 ファイルの
HTML で、外部リソースには依存しません。

## 入力の経路は 2 つある

コントローラの入力がゲームに届く経路は 2 つあります。各ゲームは **WebSocket から状態が届いている
あいだはそちらを優先し**、届いていないあいだは Gamepad API を読みます。いまどちらの経路を使って
いるかは、各ゲーム右上の HUD に出ます。

| | 経路 1: WebSocket 直結（推奨） | 経路 2: ブラウザの Gamepad API |
| --- | --- | --- |
| パッドの取り違え | 起きない | 起こり得る |
| タブのフォーカス | 外れても届き続ける | ゲームのタブにフォーカスが要る |
| 届く状態 | 改変ルールを通したあとの最終出力 | 仮想コントローラの状態 |

### 経路 1: WebSocket 直結（推奨）

LLMCon を出力先 `websocket` で起動すると、コントローラの状態が WebSocket でゲームへ直接届きます。

- パソコンに何台のコントローラがつながっていても、**パッドの取り違えが起きません**。
- ゲームのタブからフォーカスが外れても、**入力は届き続けます**。別タブのコントローラのページを
  操作しながらでも遊べます。
- 改変ルール（無効化・差し替え・連打・反転・反応遅延・アナログ変換）を**通したあとの状態**が
  届くので、改変の効果がそのまま画面に出ます。

**起動のしかた**

```
CntlLevelConnection.exe --sink vigem+websocket
```

`vigem` と `websocket` の両方を有効にすると、実際のゲームとブラウザのゲームを同時に動かせます。
`websocket` だけにすれば、ブラウザのゲームにだけ届きます。

**つなぎ方**

LLMCon と同じ機械で遊ぶなら、このフォルダの `index.html` をそのまま開くだけで
`ws://127.0.0.1:8777/vcon/ws` につながります。別の機械や別のポートの LLMCon につなぐときは、
ゲームの URL に `?ws=ホスト:ポート` を付けてください。

```
shooter.html?ws=100.119.199.18:8777
```

接続先は、(a) URL の `?ws=ホスト:ポート`、(b) ページ自身のホスト（`http://` で配信している場合）、
(c) 既定の `127.0.0.1:8777` の順に決まります。

### 経路 2: ブラウザの Gamepad API

WebSocket から状態が届いていないあいだは、各ゲームはこれまでどおりブラウザの Gamepad API で
仮想コントローラを読みます。LLMCon を `--sink vigem` だけで動かしているときや、KuriCon の
コントローラのページから入力するときはこの経路になります。制約は「[Gamepad API の認識と使い方の
注意](#gamepad-api-の認識と使い方の注意)」を参照してください。

## ゲーム一覧と操作

コントローラは標準マッピングを前提にしています（A=0, B=1, X=2, Y=3, LB=4, RB=5, LT=6, RT=7,
Back=8, Start=9, 十字=12〜15, 軸=左スティック）。どのゲームもキーボードで代替操作できます。

### 格闘ゲーム（fighting.html）

対戦格闘。CPU と 1 対 1 で戦います。

- 移動: 左スティック / 十字 / 矢印・A/D
- しゃがみ: 下　ジャンプ: 上 または LB / W
- 攻撃: A=弱パンチ(Z), B=強パンチ(X), X=弱キック(C), Y=強キック(V)
- 再戦: Start / Enter
- パッド切替: Back

攻撃にはクールダウンがあり押しっぱなしでは連射できないため、連打（turbo）改変の効果が分かりやすい
ゲームです。

### 2D プラットフォーマー（platformer.html）

横スクロールのジャンプアクション。

- 移動: 左スティック / 十字 / 矢印・WASD
- ジャンプ: A(Z)　押しっぱなしで高く、離すと弱まる
- ダッシュ: B(X) 押しっぱなし
- 最初から: Start / Enter
- パッド切替: Back

反転や遅延を掛けると、ジャンプの間合いがどれだけ狂うかを体感できます。

### 落ち物パズル（puzzle.html）

落下してくるブロックを回転・移動させて積むパズル。

- 移動: 左右（十字 / 左スティック）
- ソフトドロップ: 下
- ハードドロップ: 上 または X
- 回転: A=右回転, B=左回転
- 再開: Start
- パッド切替: Back
- キーボード代替: 移動=矢印/WASD, 回転=Z(=A)/X(=B), ハードドロップ=C(=X)/上, 再開=Enter

### ちいさな RPG（rpg.html）

マップを歩き、NPC や宝箱、看板を調べる探索ゲーム。

- 移動: 十字 / 左スティック / 矢印・WASD
- 決定・調べる: A / Z
- キャンセル: B
- メニュー: Start / Enter
- パッド切替: Back または L/R

### シューティング（shooter.html）

インベーダー風の固定画面シューティング。

- 移動: 左スティック / 十字 / ←→ / A/D
- ショット: A ボタン（押しっぱなしで連射）/ Z
- パッド切替: Back(ボタン8)

ショットの連射がボタンの押し方に依存するので、連打改変の効果を見やすいゲームです。

## 仮想コントローラでの試し方

### WebSocket 直結で試す（推奨）

1. **LLMCon を WebSocket 出力付きで起動する。**
   `CntlLevelConnection.exe --sink vigem+websocket` のように起動します。

2. **仮想コントローラに入力する。**
   物理パッドを操作する、コントローラのページのボタンを押す、あるいはマイクに音を入れるなどの
   方法で入力を送ります。ここで反転・遅延・連打・アナログ変換・マイクなどの改変を掛けると、
   LLMCon から出てくる状態が変化します。

3. **ゲームを開く。**
   このフォルダの `index.html`（ランチャー）を開き、試したいゲームを選びます。HUD に
   「経路: WebSocket」と出れば、LLMCon から直接届いています。別の機械の LLMCon につなぐときは、
   ゲームの URL に `?ws=ホスト:ポート` を付けてください。

WebSocket で届くのは改変ルールを通したあとの状態なので、改変を掛けた状態と掛けていない状態を
比べると、HUD の表示と操作感の違いがそのまま出ます。ゲームのタブからフォーカスが外れても届き
続けるので、コントローラのページとゲームをタブで行き来しながらでも確認できます。

### Gamepad API で試す

1. **KuriCon（または `--sink vigem` の LLMCon）を起動する。**
   仮想コントローラを提供するサーバを立ち上げます。KuriCon の場合、コントローラの操作ページは
   通常 `http://127.0.0.1:8788/vcon.html` にあります。

2. **仮想コントローラに入力する。**
   コントローラのページ（`vcon.html`）のボタンを押す、物理パッドを操作する、あるいはマイクに音を
   入れるなどの方法で入力を送ります。

3. **ゲームを開き、ゲームのタブにフォーカスしてから入力する。**
   改変の効果を確認するには、ブラウザが「仮想」コントローラを読んでいる必要があります。後述のとおり、
   各ゲームは最後にボタンを押したコントローラへ自動で追従するので、動かしたい仮想コントローラの
   ボタンを一度押せば、そのパッドに切り替わります。

## 実機で確認したこと

LLMCon / KuriCon が作る仮想コントローラへの入力は、ブラウザの Gamepad API まで正しく届いています。
つまり「入力が届かない」のではなく、「ゲームが読むパッドを取り違える」ことが問題でした。

パソコンには、外付けの USB パッド・本体内蔵のコントローラ・仮想コントローラなど、複数のコントローラが
同時に見えることが多くあります。ゲームがその中から違うパッドを読んでいると、仮想コントローラを操作しても
反応しないように見えてしまいます。

WebSocket 直結の経路では、LLMCon が状態を 1 本の接続で送ってくるので、この取り違えはそもそも
起きません。以下は Gamepad API の経路を使うときの話です。

## Gamepad API 経路での対応：押したパッドに自動で追従

上の取り違えを防ぐため、各ゲームは **「今まさにボタンを押したコントローラ」へ自動で操作対象を切り替える**
ようにしました。

- 動かしたいコントローラ（＝KuriCon の仮想コントローラを試すなら、KuriCon に入力を出す）の
  ボタンを一度押せば、ゲームがそのパッドに切り替わります。
- 今どのパッドを操作対象にしているかは、各ゲーム右上の **HUD** で確認できます。
- **Back ボタン**（一部のゲームでは L/R でも可）を押せば、手動でも順に切り替えられます。

WebSocket から状態が届いているあいだは、経路が揺れないように、この自動追従とパッド切替は
働きません。

## Gamepad API の認識と使い方の注意

以下は Gamepad API の経路を使うときの注意です。WebSocket 直結の経路には当てはまりません。

ブラウザの Gamepad API は、ページがコントローラを勝手に読み始めるわけではありません。挙動のクセを
押さえておくと、テストがスムーズになります。

- **まずゲームのタブにフォーカスしてから入力する。**
  ブラウザは、ゲームのタブにフォーカスした状態でボタンが押されるまでパッドを見せません。ゲームのタブを
  クリックしてフォーカスを当ててから入力してください。パッドが未認識のうちは、各ゲームが画面上に
  「コントローラのボタンを押してください」と表示します。

- **画面上のコントローラ（別タブ）はフォーカスが外れる点に注意。**
  KuriCon の画面上のコントローラ（別タブの `vcon.html`）で操作すると、その瞬間ゲームのタブから
  フォーカスが外れます。そのため、タブを行き来しながらの同時操作は難しくなります。**マイク（声でボタン）**
  や **物理パッド経由**なら、ゲームにフォーカスを当てたまま入力できるので確認しやすくなります。

- **外付け USB パッドはまぎらわしければ外す。**
  外付けの USB パッドを挿していると、それも別のパッドとして見えます。どれを操作しているか分かりにくい
  ときは、USB パッドを外すと切り分けが楽になります。

これらの制約が邪魔になるときは、LLMCon を `--sink vigem+websocket` で起動して WebSocket 直結の
経路に切り替えるのがいちばん確実です。フォーカスもパッドの選択も関係なくなります。
