# プロファイル（固定運用の設定）

プロファイルは、LLMCon を特定の用途に固定して配るための設定ファイルです。
起動引数 `--profile <path.json>` で読み込みます。コマンドラインの `--port` と `--name` の
明示指定は、プロファイルより優先されます。

```
CntlLevelConnection.exe --profile profiles\kuricon.json
```

## 項目

- `name` インスタンス名。
- `port` MCP サーバのポート。
- `bind` MCP サーバが待ち受けるアドレス。既定は `127.0.0.1`（この機械の中からのみ）。他の機械から届かせたいときだけ、
  そのアドレスを書く。LLMCon には認証の仕組みが無いので、Tailscale のような閉じたネットワークのアドレスだけに
  絞ること（`0.0.0.0` は勧めない）。ループバック以外を指定したときも、`127.0.0.1` からは引き続き使える。
- `sink` コントローラの状態の出力先。既定は `vigem`。
  - `vigem` Windows の仮想 Xbox 360 コントローラへ出す。市販のゲームに効かせるときはこれ。
  - `websocket` つながっているページへ、状態を WebSocket で配る。games/ の自作ゲーム向け。
    ブラウザがどのゲームパッドを読むかという問題が起きず、ゲームのタブからフォーカスが外れても届く。
  - `vigem+websocket` のように「+」で並べると、両方へ同時に出す。実際のゲームとブラウザのゲームを
    同時に動かせる。起動引数では `--sink vigem+websocket` と書く。
- `preset` 起動時に適用するウェブ版コントローラのプリセット名（`list_controller_presets` の名前）。
- `designHtml` プリセットの代わりに、デザインの HTML ファイルへのパスを指定する。
- `lockDesign` 真にすると、デザイン変更系のツール（set_controller_ui / set_controller_preset /
  reset_controller_ui）を拒否し、デザインを固定する。
- `ui` ネイティブのウィンドウの中身。Windows のアプリだけが使う。起動引数の `--ui` でも指定できる。
  - `status` 既定。状態の表示だけで、操作するものは置かない。動作の状態、ループの速度、選んでいる
    物理パッド、改変ルールの数、MCP とウェブ版のアドレスが出る。LLMCon は、設定と動的なデザインを
    ブラウザに置く製品なので、こちらが既定である。
  - `fighting` 状態の表示に、マイクのしきい値のつまみとレベルのメーターを添える。しきい値を
    細かく詰めたいときに開く。KuriCon はこれを使う。
  - `controller` 従来のソフトウェアコントローラ（十字、ABXY、スティック）。物理パッドが無いときに
    手早く入力を送れるので、開発用に残してある。
- `startHidden` 真にすると、起動と同時にタスクトレイへ隠れる。常駐して使う製品向け。トレイの
  アイコンからいつでも出せる。起動引数の `--start-hidden` でも指定できる。
- `mic` マイクのしきい値ボタンの既定値。`enabled`、`button`、`threshold`（0〜1）、`low`（任意）、
  `mode`（hold / toggle / tap）。
- `hidePads` 真にすると、選んだ物理パッドを LLMCon 以外の処理から隠す（HidHide が要る）。これが無いと、
  ゲームには物理パッドと仮想コントローラの両方が見え、生の入力が改変を打ち消す。格闘ゲーム用の製品では
  真にする。汎用の LLMCon では、他のアプリから物理パッドが消えて開発の妨げになるので既定は偽である。
  起動引数の `--hide-pads` と `--no-hide-pads` でも切り替えられる。
- `rules` 起動した時点から効かせる改変ルール。MCP の `set_mapping` に渡すものと同じ形で書く。
  `startSec` と `endSec` を書くと、**起動からの経過秒で効く窓**を決められる。たとえば次のように書くと、
  始めの30秒だけ Y と B が押せなくなり、そのあとは自動的に戻る。解除の操作は要らない。

  ```json
  "rules": [
    { "op": "disable", "button": "Y", "startSec": 0, "endSec": 30 },
    { "op": "disable", "button": "B", "startSec": 0, "endSec": 30 }
  ]
  ```

  **窓を数え直したいときは、MCP の `set_mapping` に同じ内容を渡す。** そこから数え直す。窓の起点は
  「アプリが動き始めた時刻」なので、起動から数秒（画面と出力の用意にかかる分）ずれることに注意する。
  ラウンドの開始に合わせたいときは、`set_mapping` で始めるほうが正確である。

  例は `kuricon-shibari.json` にある。
- `pads` 機体ごとの軸とボタンの割り当て。`vid` と `pid`（10進）、任意で `nameContains` で機体を見分け、
  `axes` と `buttons` を当てる。実測で決めた割り当てを次の起動でも使うために書く（`get_pad_profile` が
  貼り付けられる形で出す）。

## 例: kuricon.json

格闘ゲーム用の固定コントローラです。十字と、Guide を除くすべてのボタンのほか、全ボタンの反転チェックボックスと
マイク設定のパネルを持つデザイン（プリセット fighting-mic）を固定し、マイクのしきい値ボタン
（既定では RT、しきい値0.2、超えている間だけ押す）を有効にして起動します。
ポートは 8788 です（LLMCon の既定 8777 と同時に起動しても衝突しないように分けてあります。
ウェブ版コントローラは http://127.0.0.1:8788/vcon.html です）。

配布するときは、インストーラに実行ファイルとプロファイルを同梱し、ショートカットの引数に
`--profile` を付ければ、「LLMCon＋この設定」だけの単体パッケージになります。
